# Image capture 功能说明书

**版本 1.1** · 更新日期 2026-09-21 · 适用平台 Windows 10 / 11

---

## 0. 一句话说明

把不同物镜、不同分辨率、不同厂商的显微图，按**同一个物理视野（µm）**裁齐，
在成品图上加一条**比例准确、永远清晰**的新标尺，批量导出 24bit 彩色图。

典型用途：一张图里同一视野拍了好几张（不同通道 / 不同时间 / 不同重复），
要把它们裁成完全一样的视野再拼图比较；或者原图带的标尺太小太糊，
要在成品图上重新画一条干净的比例尺。

---

## 1. 支持的文件格式

| 格式 | 来源 | 标定（µm/像素）从哪来 | 备注 |
|---|---|---|---|
| `.oib` `.oif` | 奥林巴斯 | 文件内嵌 | 12bit 常见，通道名形如 `CHS1` / `TD1` |
| `.czi` | 蔡司（含 Airyscan） | 文件内嵌 | 明场常叫 `T PMT` |
| `.lif` `.lof` `.xlif` `.xlef` `.xlcf` | 徕卡 LAS X | 文件内嵌（坐标单位是米） | **一个文件里多个序列会分别列出**，命名成「文件名 · 序列 3/6」 |
| `.tif` `.tiff` | 通用 | TIFF 分辨率标签 / OME 元数据；没有就手动画线标定 | 支持多页、多通道、多帧 |
| `.png` `.jpg` `.jpeg` `.bmp` | 通用图片 | 一般没有，需手动画线标定 | 相机/手机拍的图走这条 |

其它规则：

- **通道数不限**（界面里每个通道一条卡片）；导出时的「单通道单独出图」默认提供前 3 个通道。
- **时间序列 / Z 层**统一按「帧」处理，界面出现帧滑条。
- 大图（拼图、上亿像素）可以直接读，没有像素上限。

- **滚轮规则（重要）**：鼠标在左右两栏里滚动，**只滚页面，不会误改任何参数**
  （以前的版本鼠标停在下拉框上滚一下就改数值，容易误操作，已改掉）。

## 3. 导入图片

三种方式，效果一样：

1. 点顶栏 **Get started** → 「导入文件夹（含子目录）」或「导入单个 / 多个文件…」
2. 把文件夹 / 文件**直接拖进左栏**
3. 拖进窗口任意位置（支持多选、支持混合格式）

导入后会做两件事：

- **自动分组**（见第 4 节）
- 未标定的图**不会自动跑识别**，需要你点左栏底部的「自动识别标尺」（见第 6 节）

## 4. 分组管理

### 4.1 自动分组规则

按「**图片像素尺寸 + µm/像素**」自动分组。同一台显微镜、同一个物镜、同一个视野设置拍的图会落到同一组。
组名形如 `组 3 · 0.621 µm/px · 1024×1024`。

### 4.2 手工调整

**右键任意缩略图**：

| 菜单项 | 作用 |
|---|---|
| 移动到其他组 → | 把这张图移到指定组（**移动后不会再被自动分组打回去**） |
| 设为这一组的第一张 | 让这张图成为该组的默认显示图 |
| 从列表移出（不动原文件） | 从工作列表里删掉这一张，**磁盘上的原文件一个字节都不动** |
| 打开所在文件夹 | 在资源管理器里定位原文件 |
| 复制文件路径 | 复制原文件完整路径 |

**右键左栏的组方框**：

| 菜单项 | 作用 |
|---|---|
| 重命名组… | 改成自己的名字（改过之后不会被自动标题覆盖） |
| 把当前图移入这一组 | 把中间正在显示的那张图挪进这一组 |
| 对本组未标定的图自动识别 | 只对这一组跑一次标尺识别 |
| 新建组 | 建一个空组，可以往里移图（空组会保留） |

**「清空」**：把列表里所有图移出（不动原文件）。

### 4.3 空组

图被移走或删光的组**会自动消失**，不会留下点不动的空壳。
手工「新建组」建出来的空组会保留，方便你先把组搭好再往里放图。

## 5. 裁剪视野

右栏第一张卡片，控制「要裁多大一块物理视野」。

| 项目 | 说明 |
|---|---|
| 宽 / 高 (µm) | 裁剪框的物理尺寸。默认 30 × 30 µm |
| **1:1** | 锁定正方形：改宽，高跟着变；拖框时也保持正方形 |
| **自由比例** | 宽高各调各的，长条形视野用这个 |
| **一键应用到所有组** | 把当前这组的框**大小**套到所有组；**位置各组自己保留**（放不下就靠边）。这是保证"各组视野完全一致"的正规做法 |
| 视野不足：补边 / 跳过 / 收缩 | 原图比裁剪框还小时怎么办：补黑边 / 跳过这张 / 把框缩到图片大小 |

> 切换组的时候，宽 / 高输入框会自动显示**该组自己的**框尺寸，避免误改。

## 6. 标定（µm/像素）

标定是整条链路的基础：没有 µm/像素，软件算不出物理视野，也没法画比例标尺。

### 6.1 标定的三种来源

左栏「标定」卡片下方会统计：`文件自带标定 N · 标尺识别 N · 手动 N`。

| 来源 | 何时产生 | 显示 |
|---|---|---|
| 文件自带 | OIB / CZI / LIF 读元数据时 | `OIB 内嵌标定` 等 |
| 标尺识别 + OCR | 点「自动识别标尺」 | `标尺识别 + OCR（读到 140 um）` |
| 手动画线标定 | 用画线工具自己标 | `手动画线标定` |

### 6.2 自动识别标尺

左栏底部 **自动识别标尺**：对所有还没标定的图跑一遍「找标尺横线 + OCR 认数字」，
识别成功自动填入 µm/像素。识别失败的会标注「待人工确认」。

### 6.3 手动画线标定（图片格式专用）

TIFF / PNG / JPG / BMP 这类没有内嵌标定的图，右栏「标定」卡片会显示这套工具；
**OIB / CZI / LIF 自带标定，卡片里不显示它**。

操作：

1. 点 **在图上画线** → 光标变十字
2. 在图上**对着已知长度的东西点两个点**（比如原图自带的标尺、血球计数板刻度）
3. 在旁边 **这条线代表 (µm)** 框里填这条线代表多少微米
4. 点 **应用到本组** 或 **应用到所有**

画完线后卡片里会显示 `线长 xxx.x 像素`，方便核对。
「应用到所有」只作用于**图片格式**的图，不会动显微镜下机文件。

## 7. 通道与颜色

右栏「通道与颜色」卡片，每个通道一块，只影响**显示/合成**，不改原始数据。

### 7.1 自动识别规则

- 通道名/染料名含 **T PMT、T-PMT、Transmitted、Brightfield、BF、TL、DIC、Phase contrast** → 认作**明场**，按灰底处理
- 含染料名 → 自动配色：`YFP/EYFP/Venus` → 黄，`GFP/EGFP/FITC/Alexa488` → 绿，
  `TRITC/RFP/mCherry/tdTomato/Alexa555-640` → 红，`CFP/445/458` → 青，
  `DAPI/Hoechst/405/BFP` → 蓝，`Cy5/Alexa647/647` → 品红
- 整张本来就是彩色图（合并图导出）→ 直接原样输出

### 7.2 每个通道能调什么

| 部位 | 操作 |
|---|---|
| 色点 | **点一下**弹出颜色菜单：绿 / 红 / 黄 / 青 / 品红 / 蓝 / 灰底 / 白 / 自定义取色器。「灰底」= 当明场底图叠加 |
| 通道名 | 例如 `CH1 488→520 绿`（通道名 + 激发/发射波长 + 当前颜色） |
| 左侧开关 | 这个通道参不参与合成 |
| 双端滑条 | 拖动两端调**显示区间**：左端=黑点，右端=白点（滚轮也能微调靠近指针的那一端） |
| 黑 / 白 数值框 | 也可以直接敲数字，和滑条联动 |

显示区间的初值由软件按数据分布自动给（黑点取 55 分位、白点取 99.8 分位），
12bit / 16bit 数据都不会一开始就黑成一团。

## 8. 时间序列

多帧文件（FRAP、延时拍摄）导入后：

- 中间会出现**帧滑条**，拖动逐帧预览
- 裁剪结果视图里逐帧看成品

导出时在右栏「导出内容」里选：

| 选项 | 含义 |
|---|---|
| 只出当前帧 | 导出滑条停在哪一帧 |
| 出全部帧 | 每一帧都出一张 |
| 只出指定帧 | 自己填，支持 `1,5,12` 或 `1-10` |

多帧导出的文件名会自动带帧号：`FRAPR1_f013_crop.tif`。

## 9. 新标尺

右栏「新标尺」卡片。标尺画在**成品图上**，按最终分辨率重新绘制，
**图片再糊标尺也是锐的**（4 倍超采样绘制）。

| 参数 | 可选值 | 说明 |
|---|---|---|
| 长度 (µm) | 留空 = 自动；或填固定值 | 自动取 1 / 2 / 5 × 10ⁿ 里最合适的整值（约占画面宽度 14%）。**填了就是固定物理长度** |
| 位置 | 右下角 / 左下角 / 右上角 / 左上角 / **自定义（图上拖）** | 选自定义后，**在裁剪结果里直接拖那条线或文字**，位置按组记住，导出与所见一致；旁边「复位」回到右下角 |
| 颜色 | 自动 / 白色 / 黑色 / 自定义 | 自动 = 背景深就画白、背景亮就画黑 |
| 粗细 (%) | 留空 = 5% | 占**成品宽度**的百分比 |
| 边距 (%) | 留空 = 15% | 标尺离图边的距离，同样按比例 |
| 字号 (%) | 留空 = 15.5% | 文字大小，同样按比例 |
| 字体 | Arial / Arial 粗体 / Times New Roman / Times New Roman 粗体 / 微软雅黑 / 黑体 / 宋体 | 都是 Windows 自带字体 |
| 刻度 | 两端+6 等分 / 只画两端 / 不画刻度 | |
| 带 µm | 开 / 关 | 文字里是否带单位 |
| 显示文字 | 开 / 关 | 只画线不写数字 |
| 透明标尺 PNG | 开 / 关 | 额外出一张只有标尺、背景透明的 PNG，丢进 AI/PS 里放大也不糊 |
| 导出放大 | 1×（原像素）/ 2× / 4× | 成品放大倍数；标尺按放大后的分辨率重画 |

> **粗细 / 边距 / 字号是"占成品宽度的百分比"**，每张图按自己的成品像素单独计算。
> 所以一个 93px 的小成品和一个 2947px 的大成品，标尺在画面里占的比例**完全一样**——
> 这正是"每组标尺看起来不一样大"这个老问题的解法。

## 10. 中间画布的操作

### 10.1 两种视图

| 按钮 | 显示什么 |
|---|---|
| **原图显示** | 整张原图 + 裁剪框；用于框位置、看全貌 |
| **裁剪结果** | 成品效果（裁剪 + 合成 + 标尺），所见即导出 |

### 10.2 鼠标操作

| 操作 | 效果 |
|---|---|
| 滚轮 | 以指针为中心放大 / 缩小（1× – 20×），**放大不影响裁剪框的位置和大小** |
| 按住空白处拖动 | 平移画面（放大后才有意义） |
| **双击** | 回到整图 |
| 拖裁剪框内部 | 移动裁剪框 |
| 拖裁剪框四个角 | 改变大小（1:1 模式下自动保持正方形） |
| 在裁剪结果里拖标尺 / 文字 | 自定义标尺位置（选「自定义」时） |

### 10.3 信息条

画布下方实时显示：`裁剪 ≈ 204 × 204 px`（成品像素）、`200.0 × 200.0 µm`（物理尺寸）、
以及操作提示。旁边是 **组内裁剪框位置一致** 开关（见下）。

## 11. 组内一致 vs 每张各自

中间信息条上的 **组内裁剪框位置一致**（胶囊开关）：

| 状态 | 行为 | 适用 |
|---|---|---|
| **开**（默认） | 组内所有图共用同一个裁剪框（同一视野的不同重复/通道/时间点） | 大多数情况 |
| **关** | 组内每张图可以各自摆放裁剪框位置（**大小仍然一致**） | 需要逐张微调位置时 |

不管开关在哪个状态，**组的视野大小（µm）永远是统一的**——这是软件的核心承诺。

## 12. 导出

底栏右边只有一个 **Download** 按钮，点开选范围：

| 菜单项 | 导出范围 |
|---|---|
| 只导出当前这一张 | 中间正在显示的那张（按上面的时间帧设置） |
| 只导出当前这一组 | 当前组的全部图 |
| 一键导出全部（所有组） | 所有组，按组分开文件夹 |
| 换个输出目录… | 更改输出位置 |

### 12.1 导出内容（右栏「导出内容」卡片）

| 项目 | 说明 |
|---|---|
| 合并彩色图（Merge） | 出 24bit 彩色合成图 |
| CH1 / CH2 / CH3 单独一张 | 每个通道单独出一张（只显示该通道） |
| 格式 | 跟随原图 / PNG / TIFF / JPG（默认跟随原图；TIFF 无损） |
| 后缀 | 默认 `_crop` |
| 时间帧 | 只出当前帧 / 出全部帧 / 只出指定帧 |
| 输出到 | 输出目录（默认 `程序文件夹\output`） |

### 12.2 目录与命名

```
<输出目录>\
  └─ 组 3 · 0.621 µm-px · 1024×1024\        ← 按组分文件夹
       ├─ 3164p_crop.tif                      ← 合并彩色图
       ├─ 3164p_crop_CH1绿.tif                ← 单通道（按颜色命名）
       ├─ 3164p_crop_CH3灰.tif
       └─ FRAPR1_f013_crop.tif                ← 多帧自动带帧号
```

- 输出永远是 **24bit 彩色**。
- 导出时底栏进度条走蓝色斜条纹动画，状态栏提示进度。
- 导出在**后台线程**做，界面不卡。

## 13. 程序目录里都是什么

```
ImageCapture-1.1\
├─ Image capture.exe      ← 双击这个启动（推荐）
├─ ImageCapture.vbs       ← 备用启动脚本
├─ app\                   ← 程序代码
├─ runtime\               ← 便携 Python 与依赖库（别删）
├─ assets\                ← 图标等
├─ licenses\              ← 第三方开源许可
├─ config\settings.json   ← 参数（裁剪尺寸、标尺设置、输出目录…）
├─ cache\                 ← 缩略图缓存（可以随便删）
├─ logs\app.log           ← 运行日志（出问题发这个）

└─ 使用说明.md
```

- **免安装**：整个文件夹拷到哪都能跑，不写注册表、不留后台服务；卸载就是删文件夹。
- 如果程序放在没有写入权限的地方（如 `C:\Program Files`），输出会自动改到「文档\ImageCapture\output」。

## 14. 性能与限制

### 14.1 内存估算

一张图占的内存 ≈ **宽 × 高 × 2 字节**（16bit 数据）：

| 图片尺寸 | 单张内存 |
|---|---|
| 1024×1024 | 2 MB |
| 4096×4096 | 32 MB |
| 8000×8000 | 122 MB |
| 16000×16000 | 488 MB |

导入几十张大图时，内存是所有图的总和（每张会缓存着）。
**建议单张控制在 200 MP（约 1.5 万 × 1.5 万）以内**；更大的拼图建议先用拼图软件降采样或分块。

### 14.2 速度

- 界面预览：整图挤进屏幕时只重采样一次（LANCZOS），大图约 0.4 秒
- 合成 / 裁剪：按横条分批计算，16000×16000 的图合成约 4.9 秒（在后台线程，界面不卡）
- 自动标尺识别：一张图约 1.3 秒

### 14.3 显示相关

- 整图挤进屏幕时，屏幕显示会补一点锐度（**只影响屏幕观感，导出数据一个像素都不动**）；
  放大到 1:1 时不做任何处理，保证你判断清晰度时看到的是真实数据。
- 显卡用不到，全部是 CPU 计算。

## 15. 常见问题

**Q：为什么导出的成品比共聚焦软件里看着糊？**
A：检查「导出放大」是不是设成了 2× / 4×。放大是插值，不增加任何真实细节，
在 100% 看时必然比原像素软。**要最锐就用 1×（原像素）**；确实需要大图给排版时再用 2×。

**Q：为什么有的组标尺粗、有的组细？**
A：老版本用固定像素值画标尺，而成品尺寸各组不同，所以比例不一致。
现在粗细 / 边距 / 字号都是"占成品宽度的百分比"，**各组比例自动一致**。
想整体调粗，在右栏「粗细 (%)」里填大一点（例如 6、7）。

**Q：一个 LIF 文件里有很多张图，怎么只读出来一张？**
A：已修。现在一个 LIF 里的**每个序列都会单独列出**（命名「文件名 · 序列 3/6」），
可以各自裁剪、各自导出。

**Q：裁剪框拖不到图片最下面 / 能拖出图片外？**
A：已修（1.1）。以前纵向边界用错了参数，竖构图的图会被卡住、横构图能拖出去，现在都正常。

**Q：参数老是被滚轮误改？**
A：已修。鼠标在左右两栏里滚轮**只滚页面**，不会改任何参数。

**Q：标定好的图，换个组怎么就丢了？**
A：标定是记在**图**上的，不分组。手工归过组的图再也不会被自动分组打回去（1.1 修复）。

**Q：删图会不会删掉我的原始数据？**
A：不会。所有「移出 / 删除」都只动工作列表，**磁盘上的原文件一个字节都不动**。

**Q：别人打开提示 UTF-8 解码错误 / 双击没反应？**
A：用 1.1 版本，双击 `Image capture.exe`。老版本的 `.vbs` 启动器在中文系统上会乱码，已废弃。

**Q：怎么看软件有没有出错？**
A：把 `logs\app.log` 和出问题的那张图（或截图）一起发回来即可。
